Can the SAP web interface be shown inside another page?

A test you run in your own browser. This page only loads the address you type into a frame on this page. It sends nothing anywhere, and it does not need or store any password.

Before you start. Use a normal, signed-out browser window. Do not paste a password, token or any address that contains a session key into this page or into the results. Open the browser's developer tools (F12) first, on the Network tab, so you can read the response headers in step 3.

1. Load SAP inside a frame

Paste the address of the SAP web login that students use, then press Load.

If the frame stays blank, or says it refused to connect, the server is blocking framing. That is a useful answer, not a failure of this page.

Diagnostic: messages the frame sends to this page

SAP's framing protection asks the page around it to identify itself. This log shows what it asks. The checkbox answers with the reply I believe SAP expects, which is a guess based on my memory of SAP's open-source UI5 code, so the log is the real evidence. SAP will probably still refuse until its administrators allow this page's address, but the message it shows may change.

3. Read the headers (this is the most useful part)

With the Network tab open, press Load again. Click the first request in the list (the one for the SAP address itself), open Headers, and find Response Headers. Copy the lines for these two headers if they exist, or write "none":

  • X-Frame-Options
  • Content-Security-Policy (only the part that says frame-ancestors …)

Also look at the Console tab. A blocked frame prints a red message that starts with "Refused to display". Copy that line too.
